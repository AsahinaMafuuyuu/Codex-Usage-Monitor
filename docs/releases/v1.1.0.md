# Codex Usage Monitor v1.1.0

发布日期：2026-08-28

## 相较 v1.0.0 的核心变化

`v1.1.0` 以 `v1.0.0` 的 Canonical Request 统计基线为基础，主要完成四类升级：跨 root ownership 加固、Request-day 审计语义、服务层级定价收敛，以及 Task / Canonical Requests UI 交互重构。

### 1. Canonical Request ownership 更可靠

- 修复 `history_mode=legacy` 把旧 root 历史复制到新 root 后可能触发 `canonical_requests.request_id` 全局唯一约束、重复统计 Token/Cost 的问题。
- cross-root copied Task / Request 现在只保留 inherited provenance，不再形成新的 canonical accounting unit。
- copy-first / original-later 场景支持后续回填 `canonical_request_id`；即使 copied envelope timestamp 被重写，也不会抢占原始 Request ownership。
- projection semantics 升级到 v2，但 SQLite schema 仍保持 v14；旧库只从已持久化 raw evidence 重建派生 projection，不需要 replay 或修改 `.codex`。

### 2. Request Fact / Task Day Slice 正式落地

- Time 视图不再按 Task 生命周期粗略切日，而是先按 canonical Request `observedAt` 进入本地自然日，再按原 Task 聚合成 Task Day Slice。
- Project 继续展示完整 Task `开始 / 耗时`；Time 展示 `当日首请求 / 当日末请求 / Requests`，避免把完整 Task 生命周期误当成当天计量数据。
- 新增 task-scoped Canonical Request 懒加载 API，支持 day filter、稳定 `(observedAt, requestId)` 排序、cursor/page 两种分页和 `projectionGeneration`。
- 新增 covering index `idx_canonical_requests_task_observed`，长 Task Request 审计不再依赖一次性全量加载。

### 3. Service tier 改为 explicit-fast

- 只有原始 `service_tier` 明确为 `fast` 才应用 Fast multiplier。
- `default`、`standard`、`priority`、缺失值及其他未知值统一按 standard 定价。
- UI 只显示 `standard` 或 `fast · N 倍率`；倍率直接来自 request-level pricing evidence，不再把 long-context multiplier 混入 Fast 展示。
- pricing policy 升级到 `subscription-standard-v2 / 2026-08-28-explicit-fast`；旧 calendar cost 会由持久化 canonical evidence 自动重建。

### 4. Task / Canonical Requests UI 重构

- Agent Task 取消分页，改为约 5 行高的连续纵向滚动视口；Task 仍可横向审计完整列。
- Task 滚动加入 edge chaining：内部还能滚时优先滚 Task；到顶/到底或没有纵向 overflow 时，滚轮自动继续作用于整体 workspace，不再“吞滚轮”。
- Canonical Requests 从父 Task 表 overflow 中分离为独立 drawer，父表横向滚动不会再带动 Request 标题或 Request 表。
- Request 默认 10 条/页，可切换 5/10；少于 10 条时不显示无意义分页条。
- 长分页最多保留 5 个语义槽位：首段 `1 2 3 … 尾页`、中段 `1 … 当前页 … 尾页`、尾段 `1 … 尾页-2 尾页-1 尾页`；只保留上一页/下一页。
- 分页方向按钮改用项目现有 Lucide chevron，并进行几何居中；页码、翻页内容和 drawer 展开/收起均加入轻量过渡动画，并兼容 `prefers-reduced-motion`。
- Canonical Requests 改为 single-open accordion：同时只保留最近展开的一个 Task Request drawer；旧 drawer 自动收起但保留已加载缓存。
- `N Requests` 改为明确的胶囊交互，补齐 pointer、hover、active、focus 状态。
- Task 表可见标题固定在自身容器，不再随横向列滚动。

## 稳定性与兼容性

- 不改变 `.codex` 原始 rollout；相关真实 reconciliation 保持 source hash 不变。
- SQLite schema 仍为 v14，不要求 destructive migration。
- SSE 继续使用稳定 DOM key 原位 reconcile，保留 Task 横纵滚动、Request drawer、Agent 展开和键盘焦点。
- 720px 窄屏仍保留完整审计字段与独立横向滚动。
